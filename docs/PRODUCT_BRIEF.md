# Orbit - Product Brief

## 1. プロダクト概要

Orbitは **開発作業ログ + 成長観察アプリ** である。

時間管理ツールではなく、開発者ワークフローの **ボトルネック** と **成長** を可視化することを目的とする。

## 2. なぜ作るのか

開発者の1日には、目に見えない「停滞」が大量にある:

- 仕様が曖昧で30分悩んだ
- 既存コードを探すのに1時間使った
- レビュー待ちで2時間ブロックされた
- 同じ種類のバグで3回詰まった

これらは「コミット履歴」にも「Jiraチケット」にも残らない。
結果として、**自分が何で時間を溶かしているか** を自覚できず、
**何が成長したか** を振り返ることもできない。

Orbitはこの「目に見えない開発体験」を **構造化されたログ** として残す。

## 3. ターゲットユーザー

- **Phase 1**: 自分（個人開発者・シングルユーザー）
- **Phase 2以降**: 個人開発者、小規模チームのエンジニア

## 4. コアエンティティ

| エンティティ | 説明 |
|---|---|
| **Task** | 作業の単位。GitHub Issue / Jira Ticket / 自分用TODO に相当 |
| **Work Slice** | Task内の工程区切り。「仕様確認」「実装」「テスト」など |
| **Friction** | 詰まり・ブロッカー・違和感の記録 |
| **Activity Event** | 将来のローカルAgentからのイベント（Phase 1ではAPI雛形のみ） |

### Work Sliceの工程種別（初期enum）

| Mode | 意味 |
|---|---|
| `spec` | 仕様確認 |
| `explore` | 既存コード探索 |
| `design` | 設計 |
| `implement` | 実装 |
| `test` | テスト |
| `debug` | デバッグ |
| `review` | レビュー（する/される） |
| `consult` | 相談 |
| `other` | その他（フリーテキスト補足前提） |

## 5. Phase 1 スコープ

**入れるもの**:

- Task CRUD
- Work Slice の start / end（手動）
- Work mode（工程種別）の選択
- Friction の記録
- 日次サマリ（その日の Slice 集計）
- 基本的な分析（工程別時間、Friction頻度）
- APIキーによるシングルユーザー認証
- Activity Event テーブル + ingest APIの雛形（Phase 2準備）

**入れないもの (Non-goals)**:

- マルチユーザー / チーム機能
- ローカルActivity自動収集
- AI日報の自動生成
- Growth Graphの可視化
- リアルタイム通知
- 外部サービス連携（GitHub / Slack / 等）

## 6. 将来像

| Phase | テーマ | 主要機能 |
|---|---|---|
| Phase 1 | 手動ログ MVP | Task / Slice / Friction CRUD + 日次サマリ |
| Phase 2 | ローカル収集 | Go CLI Agentでgit branch / app / windowを収集 |
| Phase 3 | AI日報 | 1日の Slice + Activity を LLM で要約 |
| Phase 4 | Growth Graph | 工程別習熟度、繰り返しFrictionの自動検出 |
| Phase 5 | Captain's Log | 週次/月次のナラティブな振り返り |

## 7. プロダクト原則

1. **プライバシー第一**
   Activity Event は将来も「ユーザー自身のもの」。AIへ送る場合は集約後のサマリのみ。

2. **記録は安く、振り返りは深く**
   入力UIは最小操作（1〜2クリック）、分析は深く。

3. **ボトルネックを可視化する**
   「速さ」ではなく「詰まり」を出す。

4. **時間管理ではない**
   工数を計るためのものではない。請求書も出さない。

5. **続けられることが最優先**
   毎日3秒で記録できなければ機能を切る。
